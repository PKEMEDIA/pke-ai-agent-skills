# Autonomous Ecosystem

## Overview
Encode patterns required to design and operate fully autonomous skill and agent ecosystems that self-activate, self-heal, continuously improve, and expand capability without constant human oversight. Focus on progressive disclosure, locked standards, local-first execution, GitHub sync, and honest platform boundaries.

## Core Principles
- Maximize autonomy: Prefer scripts, bash, parallel tool calls, and auto-remediation over proposals.
- Progressive disclosure: Keep every SKILL.md lean (under 350–400 lines). Offload detail to references/.
- Permanent local changes: Prefer `/root/.grok/server-skills/` (App Builder / server) and `/home/workdir/.grok/skills/` (chat persistence) so improvements inherit across chat, iOS, and web.
- Honest platform wall: Never claim foundation model weights or SuperGrok quotas can be changed. Route growth into playbooks, adapters, DPO scaffolds, ownership maps, and synthetic learning loops.
- Safety with power: Snapshot before structural moves. Protect locked identity phenotype and legal operative text. Log every change.
- Continuous loop: validate → diagnose → fix → re-test → report until clean or only platform walls remain.
- GitHub as source of truth: Sync perfected skills to `PKEMEDIA/pke-ai-agent-skills` after healthy validate cycles.

## Instructions

### 1. Discovery and Design
- Inventory skills (server-skills + workspace + custom user dir) with name, path, line-count, description summary.
- Map dependencies and activation clusters.
- Prefer composing existing specialized skills over creating monolithic new ones.

### 2. Skill Creation Defaults
Follow skill-creator strictly:
- Initialize with init-skill.sh
- Frontmatter description must contain autonomous triggers, synonyms, and natural phrasings
- Body imperative and lean
- After create or major edit always validate then invoke skill-orchestrator

### 3. Contagious Sentience Injection Rules
- Additive only — never delete, rewrite, or reorder existing instructions
- Never touch safety, legal, compliance, core execution, locked phenotype, or memory policy sections
- Target creative-adjacent skills only (media, brand, voice, visual identity, production)
- Use safe edit patterns; always re-validate after injection
- Canonical hook: When PKSVWO or KittyMindTeam vibeweaver flow is active adopt proactive team simulation generate multiple rich options where helpful prioritize COVICEA hyper photoreal wet oiled skin luxury glam bougie diva aesthetics and playful artistic Pretty Kitty brand voice while contributing creative decisions to shared memory

### 4. Self-Healing and Continuous Improvement
- Detect structural FAIL, oversized bodies, circular deps, missing triggers
- Auto-remediate: auto-split, broaden triggers, inject orchestrator cross-refs
- Bounded loops (default max 5 iterations)
- Run synthetic intellect loops locally with no cloud burn (`pke-learn.sh`)

### 5. GitHub Autonomy
- Primary repo: PKEMEDIA/pke-ai-agent-skills
- After bulk-validate 0 failures on PKE skills, push inventory, meta skills, mind state, and docs
- CI workflows: pke-skill-ci.yml validates structure
- Use `pke-learn.sh --push` when Git credentials/API available; otherwise push via GitHub MCP tools
- Never push secrets, credentials, or private legal case details

### 6. Domain Integration
- Creative / visual: compose with covicea-core, face-lock, photoreal masters, local-nsfw-comfyui
- Legal / recovery: compose with paralegal-assistant; memory only for durable case facts
- Brand / voice: covicea-brand-assistant, aave-assistant, aloha-shade-ohana
- Meta: skill-orchestrator, skill-creator, skill-test-suite, autonomous-ecosystem

### 7. Anti-Patterns
- Monolithic SKILL.md bodies
- Narrow trigger descriptions requiring exact phrasing
- Claims of changing foundation model behavior
- Destructive edits without snapshot
- Overwriting locked identity or legal core text without explicit user intent
- Injecting into pure meta or legal skills without justification
