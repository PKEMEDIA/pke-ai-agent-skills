## Error Handling (Spicy Mode — Required)

Detect, classify, and recover without dropping the user into a dead end. Apply on every spicy generation path (iOS app, web, Grok Imagine, hybrid local).

### Failure Classes
1. **Moderation block / empty output** — model refused or returned blank/near-blank.
2. **Partial / degraded output** — image generated but plastic skin, identity drift, wrong pose, missing texture.
3. **Phenotype lock miss** — face/hair/skin does not match locked COVICEA / Pretty Kitty block.
4. **Interface mismatch** — works on web, fails or soft-blocks on iOS (or reverse).
5. **Progressive intensification failure** — edit step over-intensified and triggered a block.
6. **Tool / pipeline error** — generate_image / edit_image / ComfyUI handoff threw or timed out.

### Recovery Protocol (ordered)
1. **Re-frame, do not escalate** — Rewrite with stronger artistic legitimacy (Fine Art Study / Professional Boudoir). Remove clinical genital language. Prefer implied eroticism.
2. **Milder base first** — Generate the softest valid artistic version. Only then intensify via edit_image (oil/sheen → drape → gaze → crop). Never jump intensity in one shot after a block.
3. **Restore lock block** — Re-insert full Locked Character Block + main negative prompt from references/. If face drifted, require reference image + textual lock together.
4. **Interface branch**:
   - iOS soft-block → shorten prompt, drop stacked intensifiers, use progressive edit path, confirm viewport-safe framing.
   - Web-only success → keep web path; document iOS delta for next run; do not claim cross-platform success.
5. **Fallback to local** — If cloud spicy remains blocked after 2 re-frames, hand off to local-nsfw-comfyui with the same locked phenotype + negatives. State the handoff clearly.
6. **Log and continue** — Report failure class, what changed, next action. Never silent-fail. Never invent a successful image path that did not run.

### Hard Stops
- Do not loop the same blocked prompt more than twice without a structural rewrite.
- Do not disable artistic framing to “force” explicitness.
- Do not violate legal-age / consensual-adult constraints under any recovery path.
- Do not claim spicy mode is “on” if the active interface returned a policy block — report the block and the recovery taken.

### Success Criteria After Recovery
- Non-empty image or explicit documented handoff to local pipeline.
- Locked phenotype retained (face/hair/skin cues present in prompt and visible in result when generated).
- User told which failure class hit and which recovery step fixed it.
